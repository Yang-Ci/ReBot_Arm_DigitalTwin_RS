# reBot Arm B601-RS 网页控制台

该目录提供 B601-RS 的 Three.js 网页模型、ROS 2 控制面板和可选的
MotorBridge 高级控制界面。它与仓库中的 `rebotarm_ros2_RS` 使用同一份 RS
URDF/STL；目录内的 `description` 只作为网页被单独复制时的离线后备。

## 当前能力

| 能力 | 状态 |
| --- | --- |
| RS Three.js/URDF/STL | 可用 |
| RS ROS 2 Fake Driver | 可用，命名空间 `/rebotarm_rs` |
| RS 真机 ROS 2 Controller | 可用，命名空间 `/rebotarm` |
| 新版 `JointPosVelCmd`/`JointMitCmd` | 已适配 |
| RS 夹爪宽度与电机角度换算 | 已适配，71.5 mm ↔ 5 rad |
| RS MuJoCo 动力学 | 可用，启动脚本默认打开 Viewer 与 physics 模式 |
| 从零点执行当前姿态 | 可用，默认回零与目标两段各 2 秒 |
| 目标鬼影生命周期 | 到位或反馈等待超时后自动隐藏 |
| 三色物体抓取环境 | 可用，含俯视相机、检测、IK 与物理抬升验证 |
| MCP/Text 抓取 Agent | 可用，MCP 默认 `http://127.0.0.1:8081/mcp` |
| MotorBridge 直连 | 保留；不能替代物理急停和后端安全层 |

## 启动网页

```bash
cd reBotArm_simulator-RS
npm start
```

浏览器访问 `http://localhost:3002`。

## 相机手势跟随（网页第一版）

```bash
npm install
npm start
```

336 深度模式需要 Python 3.9 或以上，首次安装执行 `npm run prepare:depth`。
本机已完成安装。打开 `http://localhost:3002/?view=hand-follow`，默认选择
“336 RGB-D（握拳前后跟随）”，点击“开启相机跟随”。采集由本机 Orbbec SDK 完成，
开启前关闭其他相机预览。也可选择普通 RGB 摄像头并允许浏览器相机访问。手掌左右、上下移动
带动网页机械臂末端，拇指和食指捏合控制夹爪。默认所有关节与夹爪均处于零点；
开启相机只进入待机。正对相机张开手掌持续 1 秒唤醒，机械臂平滑进入交互中位
（J2 0.45、J3 0.65、J4 0 rad，其他关节为 0，夹爪 35 mm），到位后开始跟随。
唤醒允许拇指自然弯曲，采用手指判定滞回与漏检去抖；短暂漏检只暂停进度，
不会累加到 1 秒保持时间。唤醒中断按识别结果到达时间检查，避免较慢推理反复清空进度。
首次有效输入记录起点，“重新定位”可重新记录输入起点，但不会扩大活动范围。

收到无手结果时立即暂停跟随，400 ms 内没有新的有效结果也暂停；延迟超过 300 ms
的过期识别结果不会参与跟随或唤醒。连续 15 秒没有有效手部识别
则平滑归零，保留相机等待重新唤醒。15 秒计时以最后一次有效手部识别为准，
手掌稳定可见也算有效交互。休眠按钮主动归零，关闭按钮或 Esc 同时关闭相机并归零。
归零期间不接受唤醒或跟随；主动休眠后需先收起手掌，再重新张开，防止原手势反复唤醒。
页面离开前台或相机异常时也会归零。

网页保护包括：交互中末端限制在中位周围半径 16 cm、离地高度 10–65 cm、
水平半径不超过 50 cm；交互关节使用较小活动范围；目标速度 0.15 m/s，关节速度
0.8 rad/s、加速度 1.8 rad/s²，夹爪速度 80 mm/s。中位与归零使用五次平滑插值。
无效、过期、严重出画及突跳输入会暂停交互并重新定位。
手腕、掌根轻微遮挡或出画时，以至少三个可见指根继续确定手部位置；张掌和握拳
要求至少三根可判断的手指一致，已看见的弯曲手指仍会阻止张掌唤醒。
平面跟随使用中指指根定位，避免手腕消失时目标跳动；更换定位点时重新定位。
拇指或食指尖不可见时保留夹爪开度，骨架只绘制仍可见的点和连线。
捏合距离按指根间的掌宽归一化，进入完全闭合区后输出零开度；略微放松仍保持闭合，
明显分开两指才重新打开，避免接触时识别点有间距或抖动造成夹爪留缝。
开度平滑接近目标 0.25 mm 内时准确收敛到目标，仍遵守夹爪速度限制。

“鼠标试跟随”后点击“鼠标唤醒”，可在预览区域移动鼠标或触摸拖动，验证相同的
中位、边界、暂停与 15 秒归零流程。
本入口仅更新网页 URDF，不发送 ROS 或 MotorBridge 命令，也不需要启动 MuJoCo。
336 模式同时采集 640×480 RGB 与深度，由 SDK 将深度对齐到 RGB，识别结果只使用
对应帧的掌心深度。深度区域由可见指根向掌内选取，不依赖手腕点；多个小区域
取有效深度中值，要求掌内中心与至少三个区域一致。小区域允许少量空洞，但需至少
60% 有效像素、其中 80% 深度一致；中心无效时不采用周围背景的距离。
控制范围为 260–1500 mm，建议在 300–800 mm 体验。低于 260 mm 暂停，退到 300 mm
以上才解除近距保护，避免临界距离反复切换。当前 640×480 深度模式的硬件最小距离
约 170 mm，不等于可稳定识别手势的控制范围（见
[Orbbec Gemini 330 系列数据表](https://www.orbbec.com/wp-content/uploads/2025/06/Gemini-330-series-Datasheet-V1.6.pdf)）。
空洞、背景混入、超过 300 ms 的帧和大幅距离突跳均暂停前后跟随。
握拳持续 120 ms 后进入前后跟随，距离起点取首次握拳帧；拳头远离相机时网页末端
沿基座 +X 前进，靠近相机时沿 -X 后退。2 mm 死区与自适应滤波抑制抖动，
单次前后偏移限于 ±120 mm，仍受原有中位
16 cm 活动球、关节和速度边界约束。此时不使用左右、上下或捏合夹爪输入。
前后目标最高 120 mm/s、400 mm/s²，并按当前姿态的关节余量降低速度和加速度；
小幅动作加强滤波，快动作减小滤波迟滞，短预测补偿识别延迟（最多 12 mm）。
“跟随幅度”同时调节前后映射比例，更改时重新定位，保持单次 ±120 mm 上限。
若 IK 使末端偏离锁定高度与左右位置超过 3 mm，则撤回该步并显示边界提示。
前后模式将关节位置、速度、加速度约束一起纳入求解；关节接近下限时提前制动，
并把剩余运动分配给仍有空间的关节。侧向或高度偏差到 1.5 mm 时优先修正姿态，
恢复到 0.75 mm 内后继续前后运动，避免到达硬保护线后持续卡住。
张开手掌立即退出前后模式，并以当前末端位置重新定位平面跟随，避免切换跳动。
丢手或深度空洞立即暂停输出，保持末端位置。650 ms 内的短时深度空洞、或重新入画
距离变化不超过 40 mm 的短时丢手，沿用原参考自动继续。较长中断、重新入画距离变化
超过 40 mm、异常突跳或近距保护后，需要至少三个新鲜握拳帧、持续 120 ms 确认恢复。
确认时同时把当前手距和机械臂暂停的 X 位置设为新参考，并清除旧滤波速度；第一帧
前后偏移为零，后续手部移动从当前位置接续。避免新手距套用旧起点后一直饱和在
±120 mm，或机械臂自动追赶丢手期间的移动。全局安全中心、原锁定高度和左右位置
保持不变，反复丢手不能扩大安全边界。主动张开、重新定位、调整幅度、归零或关闭
仍清除原参考。网页分别显示暂停原因和当前距离参考；状态日志同时记录手距参考与
机械臂 X 参考供排查。
恢复时继续修正锁定高度和左右位置；15 秒没有有效交互仍归零并清除起点。
已知过近输入不参与唤醒和平面跟随，无法取得有效深度的握拳不延长归零倒计时。
距离突跳按采样间隔判断，允许正常的快动作，不再把每帧超过 80 mm 一律视作异常。

当前桌面体验以实际相机固定为前提，虚拟关节姿态不被当作真实相机位姿。
未来把 336 装在随末端运动的腕部上方时，需补充该支架的外参和实际关节反馈，
再补偿相机自身运动。仓库当前 URDF 无 336 安装外参，不能用 D405 的安装参数代替。
普通 RGB 摄像头保留二维跟随，不用手部大小推算前后距离。
深度采集只允许本机同源网页调用，关闭相机、页面退出或请求中断后释放设备。
GitHub Pages 静态站点不能运行本机深度服务，应切换 RGB 模式。

启动前会准备本地 MediaPipe JS/WASM 与手部模型；首次运行需联网下载模型，之后
从本地加载。相机识别运行在 Web Worker 中，浏览器只保留一帧待处理画面。
相机访问需在 `localhost` 或 HTTPS 页面使用。

## GitHub Pages

GitHub Pages 地址：

```text
https://yang-ci.github.io/ReBot_Arm_DigitalTwin_RS/rs-console/
```

Pages 构建使用 `npm run build:pages -- ../web_mujoco/dist/rs-console`，会
复用当前仓库中的 ROS URDF、RS 手臂 STL 和夹爪 STL，输出纯静态页面；现有
`web_mujoco` 根页面保持不变。也可在本地只生成 RS 静态站点：

```bash
cd reBotArm_simulator-RS
npm run build:pages
```

注意：GitHub Pages 是 HTTPS，浏览器会阻止页面连接明文 `ws://<机器人IP>:9090`。
从 Pages 使用真机推动示教时，rosbridge 需要通过 `wss://` 提供；本地
`npm start` 页面则可以直接使用 `ws://`。AI 助手的 Node 代理同样只在本地服务
中可用，Pages 上模型、ROS 面板和示教导入导出功能不受影响。

## 启动安全仿真

先在仓库根目录构建 ROS 2 工作区：

```bash
./scripts/setup_rs_workspace.sh
```

然后启动 RS Fake Driver、MuJoCo 动力学 Viewer、抓取 Agent 和 rosbridge：

```bash
./scripts/start_rs_sim.sh
```

网页填写 `ws://<Ubuntu-IP>:9090`，选择“RS 仿真（/rebotarm_rs）”。收到
`fake_rs_pos_vel` 状态后，网页会自动允许仿真控制。

网页自然语言助手另开终端启动：

```bash
export DASHSCOPE_API_KEY="你的 Key"
./scripts/start_rs_text_agent.sh
```

## RS 真机

真机使用 SocketCAN `can0`，默认控制模式为 MIT。真机脚本设有显式保护：

```bash
export REBOTARM_RS_HARDWARE_CONFIRM=I_UNDERSTAND_RS_WILL_MOVE
./scripts/start_rs_hardware.sh
```

同时启动真机、Fake Driver 和 rosbridge：

```bash
export REBOTARM_RS_HARDWARE_CONFIRM=I_UNDERSTAND_RS_WILL_MOVE
./scripts/start_rs_dual.sh
```

执行前必须确认 `can0` 配置正确、机械臂工作区无人、物理急停可用。网页真机
模式不会自动打开控制锁。

### 推动真机示教

1. 启动 RS 真机 ROS 2 Controller 与 rosbridge，网页选择“RS 真机”。
2. 连接 rosbridge，收到 `/rebotarm/joint_states` 后打开控制锁。
3. 选择“完整路径（按原时间回放）”或“仅最终位置（3 秒到位）”，再点击
   “推动真机示教”。网页会请求进入重力补偿，成功后开始记录。
4. 用手轻推机械臂完成需要的轨迹，再点击“结束真机示教”。网页会先退出
   重力补偿，成功后自动执行安全回零。
5. 点击“回放”执行，或点击“导出 / 下载 JSON”保存；之后可用“导入 JSON”
   恢复同一条轨迹。

“完整路径”模式的数据来自 `/joint_states` 的原始 `position`，不做滤波、死区、抽稀或平滑；
时间优先使用 `header.stamp` 的整数纳秒，缺失时才回退到浏览器时钟。导出为
JSON，JavaScript number 与整数纳秒时间戳原样保留。回放同样使用原始 waypoint
和整数纳秒间隔，仅在正式轨迹前加入“当前姿态到示教起点”的安全引导段。
录制期间网页滑块、TCP 拖拽和回放命令会被拒绝，避免和人工推动互相抢控制权。
“仅最终位置”模式只保留结束示教前收到的最后一组关节位置；回放复用 IK
运动模块的平滑关节插值，从当前反馈姿态用固定 3 秒运动到该位置。

导入兼容 `rebotarm_ros_waypoints_v1` 与 `rebotarm_rs_teach_v1`。新格式会校验
关节名、点位数量、数值、时间单调性以及 `ros_stamp` 与 `time_from_start`
的一致性，避免导入被篡改或精度受损的数据。

## ROS 2 接口约定

- 关节位置速度：`/<namespace>/joints/<joint>/cmd/pos_vel`
- 关节 MIT：`/<namespace>/joints/<joint>/cmd/mit`
- 夹爪位置速度：`/<namespace>/gripper/cmd/pos_vel`
- 状态：`/<namespace>/joint_states`、`arm_status`、`gripper/state`
- 网页内部夹爪单位是米；ROS 2 夹爪电机位置单位是弧度。
